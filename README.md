# Survival Guide for MODELS Proceedings Chairs

If you're reading this, you probably have been invited to become Proceedings Chair (shortened as "ProC" in the following) for a [MODELS](https://conf.researchr.org/series/models) (or any other ACM/IEEE computer science conference) edition. Congratulations! This is a great chance to understand what happens during the camera-ready submission process from the other side. Also, we can ensure this position *will definitely* show you some of the hard work required to organize a conference that mostly goes unnoticed.

This repository contains a lot of information that we (i.e. MODELS'26 ProCs) would have liked to know before the start of our tasks. Also, this is a position that, for reasons that will soon be obvious to you, is rarely held twice. We consider that losing all the know-how gained by ProCs during each MODELS edition is a waste that makes the next ones suffer from similar (if not the same) pitfalls and challenges. We also believe part of this information can be useful for ACM/IEEE conferences other than MODELS.

The advice in this guide is organized chronologically, in the order that you are going to need it. We hope you find it useful.

## MANDATORY DISCLAIMER

The information provided is, to the best of our knowledge, valid at the time of writing these paragraphs. However, it might not be applicable to your concrete MODELS edition due to some changes in the processes, or to the editorial alternation between ACM and IEEE. So, please verify any infromation in these guidelines before its application.

MODELS editorial alternates between ACM and IEEE each edition. These guidelines were created after ACM MODELS 2026, so no specific IEEE tips are given. If you are a PC during an IEEE-managed models edition, feel free to include these tips in the same fashion we have done so for ACM.

## Before the papers arrive

### Doing the CR in August is the main issue

You must understand that many people will take annual leave (or will be already on holidays when you contact them) during the CR process. So, anything that you can prepare before August will reduce delays considerably.

### Get the full list of events that end up in the proceedings

This is fundamental to keep track of some of the steps described below. Events will be published as part of the MODELS main proceedings (Research and NIER tracks in MODELS'26) or the Companion proceedings (the other satellite events and workshops). Double-check this list with MODELS organizers so you are not missing anything.

### Ensure the Easychair events have asked for the appropriate license

Each co-located MODELS event (e.g. satellite events, workshops) will have access to the same EasyChair license as the main conference events. However, organizers of these events must ask EasyChair support themselves to obtain this license. It can be done as soon as the event has been created in EasyChair as part of a MODELS conference. We can confirm doing it *just when you need to extract the accepted papers' metadata* will translate in delays even before the camera-ready process can be started for those papers.

Two options here:

- Ensure the event organizers ask Easychair for these licenses themselves.
- If could also be possible to give Easychair a list of the co-located events, so that they can add the licenses to them in batch. Probably easier and faster than coordinating tens of event organizers (but we didn't test this).

#### ACM

These are the two EasyChair features that were needed in our case:

- Helpdesk Questions and Technical Support: useful in case things go south (we have proof of this D:)
- ACM Proceedings Management: allows exporting XML metadata in the format that can be imported into the ACM eRights system.

You will know this step has been completed successfully for an event when the organizers have given both ProCs the *volume manager (ACM Proceedings)* role.

### Give yourself a backup window

There will be a final date at which all the camera-ready papers should be 100% complete for the editorial process to have the proceedings ready for the start of the conference. Find out what date that is.

Then, what that date *cannot* be is the CR deadline for the authors. There will be a handfull of papers that will not meet the deadline for too many reasons to enumerate here. So, your maximum deadline for authors (generally the companion proceedings ones) should be something between 2 to 4 weeks earlier.

### Stagger camera-ready deadlines for main and companion proceedings

This was a great idea (thanks Mehrdad!) that allowed us to learn about the CR process with a subset of all the papers. The accepted papers of the main proceedings (e.g. Research and NIER tracks) will be accepted way before the ones that end up in the companion. Also, the main proceedings have less papers, so it is good to discover any issues and potential delays before the companion proceedings start. Having a difference of 2-3 weeks was reasonable.
